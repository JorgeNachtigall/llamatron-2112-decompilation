# Deliberate deviations from the original

Every place where the port knowingly differs from the 1992 original. Each entry says why and who owns it.

| # | Area | Original behaviour | Port behaviour | Why | Owner |
|---|------|--------------------|----------------|-----|-------|
| 1 | llatron.spl sample 30 | Sample runs 96 bytes past the end of the file (the driver plays whatever follows in memory) | Padded with silence | The bytes past EOF are undefined | W1 |
| 2 | f.cmp last glyph (chars 7D-7F) | Glyph is truncated; its missing rows come from DGROUP 409C+ (the hi-score table) | Missing rows padded blank | The original shows hi-score bytes as pixels; that is a bug, not data | W1 |
| 3 | Text on a page target (W6, text.c) | Glyph cells past the page end are written into the gap after the page and, beyond ~4.8 rows, into the next page | Cells past the page end are dropped | No caller is known to print there; callers' y ranges get checked while porting HUD/hiscore | W6 |
| 4 | Keyboard taps (W2, engine/input.c) | INT 09 runs asynchronously, so any real key press overlaps at least one frame read / timer tick | A key released before its consumer sampled it (directions: frame read 1e7b:0000, fire: tick 1000:3e12) stays held until that sample | Host events arrive in batches; press + release in one batch would otherwise be lost. Presses that span a sample behave exactly as the original | W2 |
| 5 | Sound DMA page split (W2, engine/snd.c) | A sample crossing a 64 KB DMA page is played in two transfers; the second is started from the IRQ handler (sblaster.bin 0x511), leaving a gap of microseconds | Played as one continuous block; end time = length / rate | The gap is far below one tick and inaudible; status timing is unaffected at tick resolution | W2 |
| 6 | Title sound on the web (W2, apps/title_main.c) | fs.exe requests sample 1Bh right after showing the picture | On the web the request waits until the browser's AudioContext runs (first click); natively and in test runs it is immediate | Browsers keep audio suspended until a user gesture and SDL silently drains the queue meanwhile, so the sound would otherwise never be heard | W2 |
| 7 | Scroller canvas (W6, draw_scroller.c) | The 64 KB VRAM canvas keeps whatever was in the gaps between pages | The gaps start blank | Never visible on screen | W6 |
| 8 | Entity slot searches (W5a) | Searches in enemy_init_10, the debris search and the rock search run past the 70-slot table without bound (debris/rock only with kill action 04's inherited DX=0x60) | Searches stop at the table end; with the walker past the table, the drop keeps the shot direction | Past the table is unrelated memory | W5a |
| 9 | enemy_shot_alloc with no free slot (W5a) | Callers write +3a of the nonexistent record 70 | The write is dropped | Writes past the entity table | W5a |
| 10 | P2 trail start (W4, tick.c, 1000:199d) | The loaded image has [2CF9] = 2 (not entry-aligned), and nothing resets it before P2's first trail write, so the same-position compare reads a misaligned entry | The compare uses entry 0 | At most a one-tick difference for P2, and only if those bytes equal P2's ship position | W4 |
| 11 | think_08 hunter search (W5b, 1000:4a22) | The search adds the slot number, not slot*64, so only a slot-0 llama is found (this part is reproduced). When the stray byte at table+slot is 5, it homes in on a misaligned record and later writes into it | That misaligned homing and its writes are not reproduced | It needs raw byte views of the entity table (§0.1); rare and data-dependent | W5b |
| 12 | Herder egg search (W5b, 1000:498e) | Scans past the end of the entity table when unhatched exceeds the number of llamas | Stops at the table end | Same rule as #8 | W5b |
| 13 | rescue_level_flags shift (W5b) | SAR by loop_count: an 8086 uses the full count, a 286+ masks it to 5 bits | Count mod 32 (286+/DOSBox behaviour) | Reference runs use DOSBox; only matters after 32+ loops | W5b |
| 14 | Follower trail read (W5b, 1000:194f) | Reads trail[head + follower_lag] unmasked; the overflow into P2's ring is reproduced, but past the end of P2's ring it reads whatever follows in DGROUP | Past the end of P2's ring the read wraps to P1's start | Needs about 25+ llamas in one wave with the head near the end; the memory beyond is unrelated | W5b |
| 15 | Droid recount (W5b, 1000:17ef) | Counts over the 4 records past the entity table (slots 70..73) | Treats those slots as free (entities_clear frees them) | Differs only if something writes those records | W5b |
| 16 | anim 04 on page-0 frames (W6, entities/anim.c, 1000:4646) | Its plain draw goes through sprite_draw_core, which does not preserve DI, and then anim 05 reads "the entity" through that DI: on frames drawn into page 0 (where the plain draw is not clipped away, see the x slip below) the scaled draw uses whatever DGROUP bytes the blitter's last VRAM address points at | The scaled draw uses the entity, as it does on page-1 frames | Reads unrelated memory at a VRAM-derived address; anim 04 lasts one frame (it moves on to anim 05). The x slip itself (the plain draw lands at x = [0x39d3], i.e. 0 or 0x2000) is reproduced | W6 |
| 17 | Entity draws below the page (W6, entities/anim.c) | The scaled draw always draws its first row and the horizontal beam takes any row of the 300-row table, so an entity below row 199 writes into the gap after the page and on into the next page | Cells past the page end are dropped (as #3) | Entities using those anims stay on the playfield; nothing on screen depends on it | W6 |
| 18 | sprite_draw_to_bg (W6, draw_sprite.c draw_sprite_with_background, 1000:4bd3) | Loads the page offsets 0x4000 and then [0x39d3] into AX, the blitter's x, before its two draws, so the caller's x is never used | Both draws are at the caller's x (tests/oracle/test_draw_wrappers.py runs the original's instructions with AX put back, and checks that the whole routine ignores x) | The routine has no caller in game86; the helper is for the port's own use | W6 |
| 19 | Bouncing shot reflection (W5a, bullets.c, 1000:0c8f) | The search for the shot's (direction, vx, vy) runs on past the 16 control-table entries, up to 0x6f of them, through the next tables. A match there (or in the bounce table) gives an index into whatever follows | A shot that no entry matches dies at the edge, as it does when the search runs out | player_fire and the droid only give shots table triples, and direction 0 (set by some hit handlers) never matches. Also: an entity whose sprite number has no frame has a y reach of 8 (the original reads header bytes through a link entry), and a hit handler index of 18 or more is not called | W5a |
